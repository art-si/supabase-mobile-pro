# 苹果风 Web 样板在移动端的用法

[naplesblue 的视觉样板](https://github.com/naplesblue/apple-design-skill/blob/main/reference.html)用于对照内容面、层级和材质。将适合手机的做法放进 Pro 的主题与公共组件。三端沿用各自的业务强调色和状态词；平台冲突由各应用的 Dick Wu Apple Design 审查裁决。涉及手势与弹层过渡，再用 [Emil 的交互参考](apple-fluid-interactions.md)。

| 移动场景 | 应用方式 |
| --- | --- |
| 工作台 | 冷灰页面衬托实色内容面。把同一任务的摘要、进度和下一步放在一起，只突出当前最重要的操作；辅助说明用字重、字号和留白区分。 |
| 列表与设置 | 同组短行共享一块内容面，用细分隔保持可扫读；内容较多、可独立操作的运单仍可用独立卡片。主题选择用可见名称、色板和勾标明当前状态，保存失败在原位重试。金额和时间使用等宽数字；金额摘要可按内容宽度自动并排或逐项排列，逐项排列时标签共用左边线。 |
| 表单与失败反馈 | 同一组输入共用边距、标签左线和控件高度。错误放在受影响内容或操作附近；保留已填和已加载数据，明确显示下一步。 |
| 对话与恢复 | 失败提示跟在对应的问题下方。短期失败可原问重试，会话失效可保留待发送内容后开启新对话。键盘发送或确认新对话后回到输入区；回复到达时保留用户正在浏览的位置。 |
| 导航与弹层 | 材质表达上下层关系：有内容经过的浮层可使用有限透明度并提供实色底。微信底栏保持实色，普通选中项通过图标和文字强调色及字重辨认。保留胶囊、安全区、键盘和滚动遮挡检查。 |
| 图标与操作 | 同行图文和图标底板遵循[公共对齐规则](mobile-alignment.md)。有重点时靠内容顺序与对比来突出，实测触区至少 44×44px。 |

用三个实际页面检查层级：司机任务详情先看到当前环节和下一步；货主对账详情先读到总额，再读已结算，长金额尽量保持一行；SMIS 工作台先辨认可以直接进入的作业，仅 Web 提供的条目保留可读的说明并用中性色。复用不依赖业务的强调样式和分组样式，入口、状态和业务措辞由各端管理。

改共享视觉之前，先选同一真实页面做前后图，保留长标题、失败、空状态等关键样本。H5 至少验 320px 和常用手机宽度；涉及微信外观时复看小程序实际渲染。把已验证的颜色、圆角、间距或材质回收到 `packages/mobile-core/src`，由各端按需消费。
