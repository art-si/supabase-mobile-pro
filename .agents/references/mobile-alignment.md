# 移动端图标与文字对齐

司机端、货主端和 SMIS 共用 Pro 的行布局。按控件中的实际内容决定对齐方式：

| 场景 | 对齐规则 | 公共实现 |
| --- | --- | --- |
| 短按钮、标签、行内操作 | 图标盒和可换行文字行框的垂直中心重合，同一动作栏的字高一致 | `MobileInlineLabel`；复杂插槽复用 `.mobile-inline-pair` |
| 允许换行的提示 | 图标对准第一行，文字从同一列继续换行 | `.mobile-inline-pair.mobile-inline-pair--start`，图标外包 `.mobile-inline-pair__icon` |
| 标题及补充说明组成的列表行 | 图标在整组文字的中心，标题和说明共用左边线 | `.mobile-row` 和 `.mobile-row__body` |
| 纯图标操作 | 图标在按钮的水平和垂直中心，点击区至少 44 × 44px | `MobileAction variant="icon"`；原生按钮配 `.mobile-action.mobile-action--icon` |
| 非交互图标底板 | 图标在底板的水平和垂直中心，尺寸、圆角和底色由用途决定 | `.mobile-icon-box` |
| 底部主导航 | 各项图标中心等高，标签首行对齐；短标签不随相邻入口换行移动。放大文字时也能点到第二行。 | `MobileBottomNav`；底栏与提交栏共用 `--mobile-nav-height` |

分组内的键盘焦点使用内缩轮廓。首末行的焦点轮廓沿分组圆角；单行分组四角沿用分组圆角。用真实 Tab 验收时，观察整圈轮廓以及控件与固定底栏之间的空间。

文字末尾的图标使用 `MobileInlineLabel icon-position="end"`；各页面不用单独写反向排列或给图标加纵向偏移。

多行提示的容器使用正文的字号和行高，图标槽高度从同一行高计算。避免用像素偏移或负边距修单页对齐；页面放大字体后，偏移会再次出现。

H5 的首行图标槽使用实际行高（`1lh`），不支持时回退到字号与行高倍数。浏览器仅放大文字时，图标字形保持图标盒的字号，避免笔画挤入文字。选择弹层标题变长时，关闭按钮仍占 44px。

仅放图标的按钮、背景底板和状态槽使用双轴居中；先测图标盒与底板中心的 X、Y 差，再看实际笔画中心。公共图标字体中少数不对称的字形在 `MobileIcon` 内按字号统一校正，不在页面中重复偏移。方向成对的按钮使用同系列符号。参照 Apple Design 的 `icons.md › Best practices` 和 UI UX Pro Max 的 `pro-rules.md › Icons & Visual Elements`。

微信端复查公共选择器和确认弹窗时，检查实际渲染的按钮及点击区域。专属样式要落在组件内的原生按钮上，可以复用 `.mobile-action` 的公共底样式和键盘处理。测试点击后要等弹层确实关闭、选中值确实更新，再输入或提交表单。

三个应用的微信构建启用 `mp-weixin.mergeVirtualHostAttributes`。当页面给使用虚拟根的公共控件传入样式类时，检查生成的 WXML 是否将类绑定在实际控件上。普通组件属性仍需显式传给原生节点，页面容器通过 `containerClass` 明确绑定，交互名称和禁用状态通过公共控件的属性传入。

虚拟根转发类名后，页面或复合组件的局部样式仍可能被微信组件的样式隔离挡住。卡片内边距、发送按钮和选择器旋转等影响操作的样式，要在原生画面及按钮尺寸上验证。复合公共组件可以在同一模板直接渲染原生按钮，复用 `.mobile-action` 和 `action-keyboard`，避免为穿透样式而扩大整个应用的样式隔离范围。

自定义页头在微信端需要避开状态栏和右上角胶囊；由 `MobileTopBar` 和系统安全区计算完成。页面滚动时，公共页头的底色覆盖这块区域；`revealControl` 将提示和表单控件定位在区域下方。只有宿主布局已经为整个页头保留胶囊空间时，才使用 `capsule="none"`。排班或日历的星期标题、日期、事件标记也要共用列宽与列间距；标记应占独立一行，避免有标记的日期数字上下跳动。

底部操作栏里有会换行的提示时，可用 `mobile-workspace--sticky-dock` 和 `mobile-dock--sticky`，让操作栏按实际高度占用页面空间。滚到页尾时复查最后一个字段、字数提示和底部安全区；只读时不留额外的操作栏空白。

底部提交失败提示使用 `mobile-dock__note mobile-dock__note--error` 和 `role="alert"`；普通提示复用底样式。退出确认使用 `MobileSignOutDialog`，由各应用传入自己的会话退出方法；处理期间不可重复提交，未完成退出时显示可重试的行内提示。

底部表单弹层使用 `MobileBottomSheet`：标题和关闭按钮共享一行，正文独立滚动，提交区留在底部并避开安全区。字段、错误和提交逻辑留在业务组件。嵌套选择器使用 `overlay` 插槽；H5 用 Tab、Escape 和实际点按检查最上层能独立关闭，关闭后焦点回到它自己的入口，忙碌状态不允许意外退出。

H5 弹层统一由 `useOverlayFocus` 在关闭状态生效后归还焦点。动画中断时，完成回调可能不触发。回归时也要快开快关、关闭后立即重开，并确认底层弹层不会抢走新弹层的焦点。

单日选择使用 `MobileCalendarDate`。在 320px 检查七列日期格与星期对齐、关闭和翻月翻年触区至少 44×44px；今天和已选是两种可区分的状态。键盘能在日期格内移动，取消保留原值，确定才写入，关闭后焦点回到日期入口。

操作栏与底部主导航并存时，操作栏可见期间给工作区加 `mobile-workspace--sticky-tabbed-dock`，同时给操作栏加 `mobile-dock--tabbed`。两处使用同一导航高度，正文只需要普通底部间距。复测时检查长提示、导航分界，以及完成状态是否恢复正常留白。

验收时在 320px 和常用手机宽度打开实际页面，同时查看正常内容、长文本、字号放大后的换行。表单、列表、弹层和底部导航分别走一次实际交互；微信小程序以模拟器或真机画面为准，构建结果单独记录。
